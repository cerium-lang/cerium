- [x] **H2 开放项 1「根的名字」**

- [x] **H3 开放项 2「相对路径 `self::` / `super::`」**
      结论：不引入（不是「延迟」，是判掉）。三条结构理由：文件不是命名空间 ⟹

      （`use` 里的路径本来也是绝对的，只解决一半）。

- [x] **H4 `use` 的碰撞规则**

      （原句「a reserved name at the root」删掉 at the root）。

## I. `09-match.md` 的三条 open items（2026-09-24）

一条贯穿的判断：**`match` 解构，`if` 判断。** 全文 `match` 的 scrutinee 全是枚举，
而 `if` 已是表达式（B8），这条线一旦画出，后两条的答案就跟着出来了。

- [x] **I1 字段重命名（`Int { bits: b }`）—— 判为不引入**
      必要性基本为零：① 名字更短是 cosmetic，且 `let` 里嫌字段名不好可以
      根本不解构（`let x = s.a;`）；② 遮蔽本来就允许；③ 唯一真实情形是字段名
      撞类型名 —— `Field` / `EnumField` 都有字段叫 `type`，而 `type` 也是类型名 ——
      但全文没有任何地方解构这两个结构，且绕得开（`Enum { variants }` 后索引、
      或直接字段访问）。
      代价是丢掉自解释性（`Int { bits }` vs `Int { bits: b }`）——
      与拒绝 `use X as Y` 是同一把尺子（初稿曾推荐引入，后改）。
      已落地：`09-match.md` Named payload 段 + Bindings 段。open item 删除。
      状态：已定
- [x] **I2 or-pattern / range / guard —— 拆成三个决定**
      - **or-pattern：要**。`|` 在 xyz 里是空的（只有 `||`），代价是一条规则：
        各分支必须绑定相同的名字与类型（`Some(x) | Other(x)` ✓，`Some(x) | Other(y)` ❌）。
        真实用例：`match @typeinfo<T>() { Int { .. } | Float { .. } => "number", ... }`。
      - **guard：不要**。`if` 已是表达式，判断放进 arm 即可；更关键的是保住
        穷尽性规则的干净 —— 带 guard 的 arm 不算覆盖其模式（Rust 的已知别扭处），
        不加则「覆盖所有变体或用 `_`」就是完整的一条。
      - **range：不要**。只对整数匹配有意义（而整数匹配判为不做）；
        且 `..` 已有两种含义（切片半开、结构体模式「忽略其余」），再加是第三种，
        还要额外定开闭（`..` 还是 `..=`）。

      no literal patterns`。open item 删除。

      关键事实：`enum X(u32) { A = 0, B, C, D = 10, E }` —— xyz 的枚举能指定
      tag 类型与**显式判别值**。于是整数匹配的两类真实用途各有更好去处：
      ① 操作码/状态码/错误码分派 → 枚举，**且能被穷尽检查**（整数永不穷尽、
