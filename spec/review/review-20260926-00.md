- [x] **J2 没有运算符优先级与结合性表**
      现状：`07-operators.md` 定义了运算符如何脱糖到 trait 方法，但没说 `a + b * c` 怎么解析。
      相关：`08-reflection.md` Lifting and splicing 段规定 `^^` 是一元前缀记号而非两个 `^`
      （`^` 是 xor），说明词法层面已经被迫做过一次决定 —— 这类决定还缺一整张表。
      候选：
        A. 沿用 C 的优先级表（熟悉、无惊喜）；
        B. 沿用 Rust 的（与现有语法的相似度更高）；
        C. 大幅简化 —— 强制括号，只保留少数几级（Go 式或更激进）。
      要决定的问题：混合算术与比较时是否要求显式括号？`a < b == c` 要不要合法？
      结论（2026-09-26，随 J1 段二落地 `15-grammar.md` Expressions 节）：
        - **主干跟 C/Rust**：乘 > 加 > 位and > 位xor > 位or > 关系 > `&&` > `||`，
          左结合；位运算按 C 拆三级（`&` > `^` > `|`）。
        - **关系同级不可链（Swift 式防呆）**：`a < b < c` / `a < b == c` 是语法错误，
          连续比较几乎总是数学意图的 bug；bool 比较 `(a < b) == (c < d)` 写括号。
          `&&`/`||` 照常可链（短路链是常态形态）。
        - **赋值是语句不是表达式**（Zig 式）：`a = b = c` 不是形式，右结合问题不存在。
        - **`^^`/`$$` prefix-only**：`a ^^ b` 语法错误（`08` 已定，文法收编）。
        - **v0 无移位、无 `~`**：正文零用例；token 表无 `<<`/`>>`/`~`，
          `is_same<i32, i32>>()` 的 `>>` 天然是两个 `>` —— 嵌套泛型零特殊规则。
          引入移位的成本（lexer 拆 `>>`，Rust 的账）记入 `15` 开放项。
        - **泛型调用 vs 比较的 `<`**：identifier 后贪婪尝试 generic_args，
          闭合 `>` 后跟 `(`/`::`/`.` 才是泛型，否则回退比较（`f<T>(x)` vs `a < b`）。
        - **struct literal 位置限制**：if 条件与 match scrutinee 处（block 将开场）
          需括号 —— `if Point{...} == q` 非法，`if (Point{...}) == q` 合法。
        - **裸 block 不是表达式**：block 只出现在 if 分支 / match arm / 函数体。
        - `?` 传播是后缀（最紧一级）。
      已落地（2026-09-26）：`15-grammar.md` 优先级表 + 产生式 + 决定叙述。
      追加（2026-09-26，PR #8）：**移位引入，`>>` 采纳 Rust 拆分方案**（用户确认）——
      `<<` `>>` `~` `<<=` `>>=` 入 token 表；shift 级插在 additive 与 bit and 之间
      （C 位）；`~` 补进一元层（`!` 是 bool 专用，整数按位反原来无记号）；
      **`>>` 拆分只在 generic_args 闭合点**：lexer 恒发单 token，parser 只在该产生式
      处拆（表达式与类型文法共用），泛型 vs 比较的既有 lookahead 不变。
      语义（`07` What is not a trait 补 Shifts 段）：有符号 `>>` 算术移位、无符号
      逻辑移位（无 `>>>`——无符号类型已表达）；移位量 `>=` 位宽：运行期 panic
      （"shift amount out of range"，one mechanism）、编译期常量则编译错（与常量
      索引越界同一笔交易）；无 trait（built-in for integers，与 `%`/位运算同档）。
      否决：`@shl` 函数形态（高频运算撑不住）、只加 `<<` 不对称、泛型改 `f[i32]`
      （倒因为果）。`15` 开放项删移位条；顺手修段二悬空的 `cmp_operator` 引用。
      状态：已落地

- [x] **J3 `?` 一身三用的词法消歧**
      现状：类型后缀 `?T`（`Option<T>`）与 `E?T`（`Result<T, E>`）、可空指针 `?*T`、
      错误传播运算符 `f()?`（`05-traits.md` Result 段：「no `try`, no exception」）。
      同一个字符在类型位置和表达式位置含义不同，且与 `?` 作为三元/可选链的直觉冲突。
      为什么阻塞：这是词法层面的歧义，必须在写 lexer 前定掉。
      候选：
        A. 保持现状，靠位置区分（类型位置 vs 值位置）；
        B. 传播改用别的记号（如 `try f()`、`f()!`）；
        C. 类型后缀改用别的记号。
      要决定的问题：`Result` 的 `E?T` 写法（错误类型在前）在读到 `E?` 之前无法判定是
      `E` 的类型还是错误类型，词法上要不要给解析器一点提示？
      结论（2026-09-26，随 J1 段二落地 `15-grammar.md` Types 节）：**A，位置消歧正式化**：
        - 类型文法 `result_type = prefix_type [ "?" prefix_type ]` —— `E?T` 一步解析，
          E 省略即 `?T`；两侧皆可嵌套（`E??T` = `Result<Option<T>, E>`）。
        - 表达式 `?` 只有后缀传播（`f()?`），表达式头部出现 `?` 是语法错误。
        - 两套文法不相交，**无需 lexer 提示**——位置即决定。
      已落地（2026-09-26）：`15-grammar.md` Types 节 + The `?` three ways 小节。
      状态：已落地

- [x] **J4 `[` 的七种用法**
      现状：数组类型 `[N]T`；切片类型 `[]T` / `[]mut T`；闭包捕获列表 `fn[x]` /
      `fn[mut n]` / `fn[&mut total]`；索引 `a[i]`；切片区间 `a[1..]`；
      数组字面量 `[3]u32{1, 2, 3}`；属性 `#[...]`（N1 定案后新增）。
      类型位置和表达式位置的区分多半够用，但 `fn[]` 与 `[]T` 相邻出现时需要确认。
      属性那一笔是 `#` 打头且只出现在 item 与参数列表开头，不进表达式解析路径 ——
      对 J2 的优先级表与 J3 的消歧没有影响。
      要决定的问题：捕获列表是否值得独占一个记号（如 `fn|x|`）来换取可读性？
      结论（2026-09-26，随 J1 段二落地 `15-grammar.md`）：
        - 七用各自有产生式：类型前缀（`[N]T` / `[N]mut T` / `[]T` / `[]mut T`）、
          表达式开头的数组字面量（表达式位置唯一合法的 `[` 开头）、
          postfix 索引与区间（`a[i]` / `a[1..2]` / `a[..]`）、`fn` 后捕获列表、
          `#[` 词法 token。
        - **捕获列表保留 `fn[`**：`fn` 是关键字，`[` 紧跟其后不歧义，
          不换 `fn|x|` —— 现有记号无消歧成本，换记号只添一族 token。
      已落地（2026-09-26）：`15-grammar.md` The brackets 小节。
      状态：已落地

- [x] **J5 `for` 三形态消歧，以及 C 风格三段式是否就此消失**
      现状：`10-iteration.md` 的 For 段：`for cond` / `for let PAT = e` / `for PAT in c`，
      靠 `let` 与 `in` 两个记号区分，并说「`in` 出现在语言别处没有，所以一个记号足够」。
      最新提交把 `while` 并入了 `for`（`for cond` 即原来的 `while`），
      但规范里现在没有任何 C 风格 `for (init; cond; step)` 的位置。
      为什么阻塞：不是实现阻塞，是表达力缺口 —— 需要「初始化 + 条件 + 步进」且步进
      不是简单推进迭代器的循环，目前只能写成 `for cond` 加手动维护变量。
      候选：
        A. 接受 —— 用 `for cond` + `mut` 变量写，或者写一个 `Iterator`；
        B. 加第四种形态 `for init; cond; step`；
        C. 由 `Range` + `for in` 覆盖（需要 `Range` 类型和步进支持）。
      要决定的问题：这是刻意的收窄（Zig 也只有 `while` 和 `for`），还是漏了？
      结论（2026-09-26，随 J1 段三落地 `15-grammar.md` The for shapes）：**A，刻意收窄**：
        - 三形态文法闭合：`let` 开头即 for let；否则按 expression 解析，
          后遇 `in` 回读为 pattern（表达式与 pattern 同形，回读零成本）。
        - **C 三段式不引入**：`for cond` + 前置 `let mut` + 体尾步进表达力等价，
          步进即推进时 Iterator 更好；Zig 同款取舍（`while` + `for`，无第三头）。
        - **range 缺口记为开放项**：`..` 只在索引括号内；`for i in 0..10` 需要
          `Range` 迭代器 + range 表达式 —— 需要出现时再加，是加法不是文法缺口。
      已落地（2026-09-26）：`15-grammar.md` for_statement 产生式 + The for shapes 小节。
      追加（2026-09-26，PR #8）：**range 引入，J5 的缺口关闭**（用户确认）——
      `a..b` 表达式（`range_expr = or_expr [ ".." or_expr ]`，loosest 级，一条
      产生式两条链之间，每表达式至多一个）；**半开区间**；无 `..=`（闭端写
      `0..(n+1)`）；开区间形态 `..n`/`n..` 不做（索引括号专属，纯表达式无 end 可言）；
      `Range<T>{start,end}` + `impl Iterator`（T: Copy，整数起步）落 `10` 新
      Range 小节；`for i in 0..10` 走既有 for in；`a[1..3]` 保持索引位置的糖，
      **不**统一成传 range 值（slice 是 borrow 语义、range 是值语义，统一要付
      borrow 检查的账）。`15` 开放项清零。
      状态：已落地

- [x] **J6 字面量与词法基础未定义**
      现状：整数字面量的进制与分隔符、有无类型后缀、浮点形式、`char` 与字符串转义、
      注释形式（`//` / `/* */` / 嵌套）、原始字符串（`01-types.md` Raw String 段有，
      但没说定界规则）、分号与尾随逗号是否可选。
      为什么阻塞：lexer 的第一批规则，不定就没法写 tokenizer。
      要决定的问题：要不要数字分隔符（`1_000_000`）？注释要不要支持嵌套？
      结论（2026-09-26，随 J1 段一落地 `15-grammar.md`）：
        - **注释**：`//` 行注释 + `/* */` 嵌套（必须闭合，不闭合是词法错误）。
        - **分隔符**：`_` 两侧各需一个 digit —— `1_000_000` ✅、`1__0` / `1000_` ❌、
          `_1000` 是 identifier。
        - **进制**：十进制 / `0x` / `0o` / `0b`；无类型后缀（`42u8` 不是形式），
          unsuffixed int → `i32`、float → `f32`（`01` 已有）；负号不是字面量的一部分。
        - **浮点**：仅十进制；`.` 两侧都必须有 digit（`1.` / `.5` 非法）；
          指数 `e[+-]d+`；无小数点有指数（`42e3`）也是 float；无 hex float。
        - **转义集（封闭）**：`\n \t \r \0 \' \" \\ \xNN`（NN 到 `0xFF`，元素是字节，
          字符串是 `[]u8`）；**无 `\u{...}`** —— 源文件是 UTF-8，非 ASCII 字符直接写本体。
        - **字符串前缀**：`c` / `r` / `cr`，前缀必须紧贴 `"`（`c "..."` 是两个 token）；
          raw 无转义、不能含 `"`、无 `r#"..."#` 嵌套（`01` 已定，文法收编）；
          **单行字面量不跨行**。
        - **源文件**：UTF-8，CRLF 归一为 LF，开头 BOM 跳过。
        - 分号/尾随逗号属语法层，段二、段三定。
        - 开放项：Unicode identifier。
      追加（2026-09-26，PR #8）：**多行字符串落地**（用户拍板「要支持下」）——
      Swift 式 `"""`：开引号后必须换行（不进内容）、闭引号独占一行（其前换行不进
      内容）、**闭引号缩进即剥离线**（每内容行剥掉等量前导空白，剥不够是词法错误，
      空行豁免；tab/space 逐字符匹配，混用报错不悄悄错位）；plain 版 8 转义照常、
      raw 版无转义且行内 `"""` 不可表示（plain `\"` 或拼接）；`c`/`r`/`cr` 前缀
      原样组合。备选否决：Zig `\\` 行首（每行噪音）、Python 原样缩进（缩进代码里
      全是垃圾空白）。`01` String 节补 Multiline String 段。
      追加（2026-09-26，PR #8）：**Unicode identifier 关闭**（用户确认）——
      v0 锁 ASCII：将来放开是纯加法、开后收窄是破坏性变更，风险不对称；
      注释与字符串照常任意字节。`15` Source text 句子改定案。
      已落地（2026-09-26）：`15-grammar.md` Source text / Integer / Float /
      Byte and string literals 各节 + Multiline strings 小节；`01-types.md`
      Multiline String 段。
      状态：已落地

- [x] **K1 没有 ABI / FFI / `unsafe` —— 最要命的一条**
      现状：`01-types.md` Functions 段与 `05-traits.md` Result 段都把 `print` 和 `panic`
      说成「`std` 里的普通函数」，可语言自身没有任何触达系统调用的能力。
      没有 FFI，一个不能 IO 的语言在原理上无法写出 hello world。
      `extern` 只在 `11-namespaces.md` 的开放项和 `README.md` 里出现，未定义。
      候选：
        A. 定义 C ABI 的外部函数声明即可，不引入 `unsafe`；
        B. 引入 `extern` + `unsafe` 块，把「越界/悬垂/别名/FFI」四类交给 `unsafe` 标记；
        C. 不定义 FFI，v0 只做纯计算（能编译、能检查、不能落地）。
      结论：**A，且 `extern` 不作为关键字 —— 改为属性 `#[extern(C)]`。**
        - `#[extern(C)]` + 无函数体 = import；`#[extern(C)]` + 有函数体 = export。
        - `pub` 保留，与 `#[extern(C)]` 是两件事：`pub` 管其他 xyz 代码能不能调，

          函数符号必须 mangle —— 所以 `pub fn` 导出的符号不叫它在源码里的名字，
          C 那边按字面名找不到。`#[extern(C)]` 标记的是「这个符号按 C 的规则暴露」，
          `pub` 表达不了这件事。
        - 不引入 `unsafe`：xyz 普通代码跨函数边界就已经是 UB（README 的
          Deliberately unchecked 一档），`unsafe` 只能表示「比 UB 更 UB」，语义可疑；
          且 README 已有四档保证，加第五档比加一个关键字便宜。
        - ABI 名字放在属性参数里（`(C)`），不在语法层造 ABI 命名空间。
      已落地（2026-09-26）：`01-types.md` Functions 段新增 `### External functions`

      现状：规范里没有 `main`，没有「一个文件 / 一个目录 / 一个库是什么」，

      结论（2026-09-26 全案）：
        - **编译单元 = 整个项目**（根目录树），v0 无分离编译。
          地基是三个既有事实：`04` 的「实例化全局发一份」、`04` 的

          （著名痛点）；C++ 的模板要求定义可见 → 头文件地狱 + 链接期去重。
          xyz 把妥协反向拿：视野换编译速度。

          构建模式、控制流、测试；入口是**角色**不是性质，角色用名字表达
          （C / Rust / Zig 全是 `main`）。`#[main]` 会把属性族稀释成「万物皆可标」。
          `main` 不进关键字表（J7 不动）—— 普通名字，编译器按约定找。
          mangle 不管：平台入口符号由编译器的 shim 安排（unmangled 的 C `main`
          调 xyz 的 `main`），规范只说「编译器安排平台入口」。

          | panic | `abort()`（SIGABRT，K4d） |

- [x] **K3 没有堆与 allocator**
      现状：`01-types.md` Slice 段明说切片「never allocates」；`10-iteration.md` 的迭代器
      全部栈上。规范里没有出现任何一个 growable 容器，也没有分配/释放的概念。
      为什么阻塞：不是「写不了 `Vec`」，而是「`Vec` 该由谁写、按什么接口写」没有答案 ——
      没有 `unsafe`（K1）就没有写 allocator 的合法位置。
      结论（2026-09-26 全案）：
        - **Allocator 是容器的泛型参数**（用户定案，Zig 式）：`struct Vec<T, A: Allocator>`
          —— `alloc: A` 按值持有（xyz 无引用；多数 allocator 是零大小标记类型，
          真有状态的 arena 就 move 进容器，所有权清楚）。默认走 `04` 的
          Defaults：`Vec<T, A = Heap>`，不写即 `std` 的系统分配器。
        - **a1：`std` 提供系统 allocator**（`std::mem::Heap`）。实现是平台代码，
          内部用 `#[extern(C)]` 调 `malloc` / `mmap` —— 那是 std 的地盘不是用户的，
          K1 的「无 unsafe」与用户侧保证不变。未采纳 a2（`alloc`/`free` 原语进
          builtin —— `@` 家族膨胀、slice never allocates 破功）与 a3（留白 ——
          v0 连 `Vec` 都没有，等于没解）。
        - **trait 签名（用户定案，untyped，无 Layout）**：
          ```rust
          // in std::mem
          enum AllocError { OutOfMemory }

          trait Allocator {
            fn alloc(self: *Self, size: usize, align: usize) -> AllocError?[]u8;
            fn free(self: *Self, buf: []u8) -> ();
          }
          ```
          - 返回 **`AllocError?[]u8`** 不是 `?[]u8`（用户定案）：命名 enum
            将来加变体不破签名；Some/None 表达不了「为什么失败」。
            分配失败的两种实况各走各的糖：返回 null 走 null-capable，
            正式返 Err 走 error forwarding。
          - **不要 `Layout` 封装**（用户定案，推翻本人早先提议）：两个裸
            `usize` 直接传。理由：DTO 会卷进反射体系（`@typeinfo` 描述、
            序列化 walk、`is_same` 撞名），纯搬运参数不值得；Zig 先例同侧
            （`alloc` 直接推参数，不搞 Layout；Rust 用 Layout 是因为
            GlobalAlloc 是跨边界的 unsafe hook）。
          - **untyped，不返回 `[]mut T`**（用户否了 typed 版）：`alloc<T>` 泛型方法
            会让 `dyn Allocator` 没戏（vtable 装不下单态化）。容器侧
            `[]u8` → `[]mut T` 的转换留给 std 的转换函数。
          - **返回 slice 不返回 `?*u8`**（讨论定案）：分配产物天生是 (地址, 长度)
            二元组；slice 有 debug 边界检查而 `*u8` 行走无检查；`01` Pointer 段
            已把分工画好 —— 指针算术是 allocator **内部**走块的工具，
            对**外**的接口给 slice；Rust Allocator 也返回胖指针（`NonNull<[u8]>`）、
            Zig 返回 `[]T`。
          - **`free` 单参数**（讨论定案）：长度已在 `[]u8` 里（类型保证），
            分配器还块靠自己的元数据反查（块头 / size class），不信调用者报的
            Layout —— 传了要么被忽略、要么被错误信任。Rust `deallocate(ptr, layout)`
            成对传是因为它返回裸指针长度不在值里；xyz 的 slice 出厂自带。
            对称性在信息流向不在参数个数：alloc 是调用者→分配器（布局在调用点），
            free 是值本身→分配器（长度在类型里）。
        - **trait 参数不走 `const`**：`dyn Allocator` 的方法必须可动态分发
          （const 方法禁取值，N7）；静态分配器自己优化。
        - **slice never allocates 不破功**：切片仍然不分配 —— 分配的是
          allocator（函数调用），slice 只是分配结果的载体。
        - **命名空间定 `std::mem`**（用户定案，2026-09-26）：`Allocator` /
          `AllocError` / `Heap` 与 `@take` 家族（take / swap / zeroes）同住 mem。
          未采纳 `std::heap`（Allocator 是抽象接口，arena / pool 不是堆，
          名字撒谎；但 `Heap` 与命名空间同名也有自洽性）与 `std::alloc`
          （折中候选）。mem 的辩护：分配器就是「内存来源」，与值的操作
          （take / swap）同属 mem 主题；Rust 的 `std::mem` 放 `take` /
          `swap` / `replace`，Zig 的 `std.mem` 放 `copy` / `zeroes` ——
          两个先例 mem 都不碰分配器，xyz 走自己的路。
      已落地（2026-09-26）：`01-types.md` 新增 `## Allocation` 段。
      状态：已落地

- [x] **K4c 返回类型 / divergence —— 新发现的缺口**
      现状：`10-iteration.md` Divergence 段明确 xyz 没有 `never` 类型，且 divergence

## N. 属性族、`assert` 与反射改动

讨论 K1 时长出来的。属性不是宏 —— 不生成代码、不可扩展、不重写语法，
只是编译器认识的固定标记（用户原话：「`#xxx` 是属性 不是宏」）。
字母编号按主题排：N1–N3 属性，N4–N5 断言，N6 宏，N7–N8 反射，N9 测试。

- [x] **N1 属性的语法与结构**
      结论：
        - **写法 `#[...]`** —— 有边界，好解析；无参数的属性也清楚。
          （此前记作 `#xxx`，旧写法已在全节更新为 `#[...]`。）
        - **多个属性两种写法都合法**（Rust 的做法）：
          `#[packed] #[build(debug)]` 与 `#[packed, build(debug)]`。
          注意与 `#[build(debug, release)]` 区分 —— 那是一个属性多个参数。
        - **结构**（`08-reflection.md` 的 `std::meta`）：
          ```rust
          struct Attr { name: []u8, args: []AttrArg }
          enum AttrArg { Ident([]u8), Int(i64), Str([]u8) }   // 不嵌套
          ```
        - **参数是普通 identifier 或字面量**，不是表达式、不是枚举，由属性自己解释
          —— 印证「属性不是函数也不是宏」。
        - **可标位置**：struct / union / enum 声明、enum variant、字段、**函数参数**、
          函数声明。语句与表达式上不允许 —— 属性不进入表达式 / 语句的解析路径，
          利好 J2 的优先级表和 J4 的 `[` 消歧。（参数上允许标，但反射读不到 —— 见 N8。）
        - **两类属性**：编译器消费的（`#[packed]` `#[align]` `#[extern]` `#[build]`
          `#[test]` `#[noreturn]`）与用户反射消费的（`#[skip]` 等，进 `TypeInfo` 的
          `attrs`）。
          前者不需要反射读取 —— 函数**声明**的元信息因此不做，`@fninfo` 不引入。
      已落地（2026-09-26）：`01-types.md` 新增 `## Attributes` 段（语法、两种写法、
      可标位置、参数形态、语言属性表、用户属性走反射）。`#[test]` 未进正文清单
      —— 等 N9 定完再进。
      状态：已落地

      结论：**普通函数 + `#[build(debug)]`**，放在 `std::debug`（该名字由此名副其实）：
      ```rust
      #[build(debug)]
      fn assert(cond: bool) { if !cond { panic("assertion failed"); } }

      #[build(debug)]
      fn assert(cond: bool, msg: []u8) { if !cond { panic(msg); } }
      ```

      `assert!`（宏）→ 回到普通函数。转向宏的理由是「作为函数太薄」：
      拿不到表达式文本、位置依赖构建、release 下关不掉 —— 第三条随后由
      `#[build(debug)]` 解除，于是回到函数。
      接受的限制：表达式文本 ❌ / 位置依赖构建 ⚠️（靠 `panic` 内部的 backtrace，见 K7）。
      **`assert` 只做运行期** —— 编译期那半暂不引入（N5）。

          （函数类型没有声明位置，`fn(u32) -> u32` 直接写在类型标注里就能用）。
          为什么一级（用户定案）：`*fn(A) -> B` 若函数包在 `Pointer` 里会出现

          在 `std::meta` 下，同 `Struct` / `Enum` variant 与关键字同名的先例。

          （N8 落 A），恒空不留字段 —— 与内建 variant 不带 attrs 同一条原则。
        - **`Optional` / `Result` variant（2026-09-26 定，推翻 D2 的反射分流）**：
          `Optional { child: type }`、`Result { ok: type, err: type }`，
          `?T` / `E?T` 一律进自己的 variant，不论有没有 niche。
          动机（用户发现）：`?` 是 `Option<T>` 的语法糖，`optional: true`
          却在讲「这个 Option 走了 niche 布局」—— 纯布局事实进了 `TypeInfo`，
          与删 `Repr` 的理由（布局不解码，靠 `@sizeof`）双标。
          方案（用户定案：学 Zig）：`Pointer` / `Slice` / `Fn` 的 `optional`
          字段全部删除；`?*T` 是 `Optional { child: Pointer{..} }`，
          `?u32` 是 `Optional { child: Int{..} }`；`E?T` 对称走 `Result`。
          Zig 同款结构（`std.builtin.Type`：`optional: Optional` / `error_union`）。
          **D2 前半不动**（`None` / `Some` / `match` / narrowing 对一切 `?T` 一致，
          布局 niche 分流仍是 `02` / `@sizeof` 的事实）；被推翻的是「反射分两路」
          与「`TypeInfo` 不设 `Optional` 变体」两句。`?u32` 塞 `Enum` 会谎报
          tag（`?*T` 无 tag），所以不能走「统一变 `Enum`」那条路。
          泛型代码的收益：识别「可空 / 可错」从两种路径（`Pointer` 带 flag /
          `Enum` 猜 None/Some 形状）变成 match 一个 variant。
      连锁（均已定，2026-09-26）：
        - **`#[noreturn]` 过函数指针即丢**：noreturn 是声明属性不进类型，
          `let f: fn([]u8) -> () = panic;` 合法，但 `f("x")` 不 diverge ——
          编译器照常检查其后的代码（运行期无影响：panic 真的 abort 了）。
          Rust 用 `fn() -> !` 类型保住这条；xyz 接受丢失 —— `#[noreturn]`
          的第二条已知代价（第一条是 `10` 的浅判断放宽）。
        - **带 `const` 参数的函数不能作为值使用（已定）**：赋函数指针、
          作实参、作类型参数都是编译错误。理由：实参烘焙进实例化，
          指针调用没处递 `const` 实参，还会静默绕过编译期已知检查
          （`g(runtime_string)`）。要两用就写两个函数，`const` 版委托普通版。
          Zig 的 comptime 参数同款限制（其 `TypeInfo.Fn.Param.is_generic` +
          `type: ?type` 记录此事）。已落 `08` Const parameters 段。
        - **`#[extern(C)]` 不改调用约定（已定，方案 a）**：xyz 默认约定
          **就是**平台 C 约定 —— 寄存器、栈序，除符号名外全部一致。
          连带：`#[extern(C)]` 函数与普通函数是同一函数类型，可自由作为值
          传递。将来想要更快私有约定的编译器可以整体换 —— 只要它编译
          全程序、约定不越过它自己选的边界。已落 `01` External functions 段
          （首句 "under the C calling convention" 改为 "under the C rules"）。
          未采纳 b（约定进类型，Rust/Zig 的做法）：函数类型分裂，
          xyz 只有两个约定时复杂度不值。
      已落地（2026-09-26）：`08` TypeInfo 段 —— `Struct` / `Union` /
      `Field` / `EnumField` 的 `attrs`、`Attr` / `AttrArg` 定义、`Repr` 枚举删除
      （含「布局不解码，靠 `@sizeof` / `@alignof` / `@offset`」的说明）、
      `Fn` variant 与 `struct FnArg`（一级、不挂 `Pointer` 下的说明与理由）、
      `Optional` / `Result` variant（`optional` 字段全删、分流段重写）；
      `01` Nullability 段反射句同步；`08` Const parameters 段（const 函数
      禁取值 + 两函数模式）；`01` External functions 段（方案 a 三段）。
      状态：已落地（全部闭合）

- [ ] **N8 参数上的属性目前无处可读**
      现状：N1 允许 `fn f(#[unused] x: u32)`，但反射侧拿不到它：
      `TypeInfo::Function` 描述的是**函数类型** `@typeinfo<fn(u32) -> u32>()`，
      参数在这里只是一串类型，没有名字也没有属性；而函数**声明**的元信息（N1）不做，
      `@fninfo` 不引入。即：参数属性既不是编译器消费的（现在没有这样的属性），
      也进不了 `TypeInfo`（没有承载它的声明节点）—— 标了没人读。
      候选：
        A. 参数属性 = 编译器消费，与 `#[extern]` 同类，反射不管。
        B. 为读参数属性引入函数声明反射入口 —— 即复活 `@fninfo`（2026-09-26 已明确不引入）。
        C. 就是死语法，等出现真实消费者再补语义。
      结论（2026-09-26）：**A**。`FnArg` 结构（N7）不带 `attrs`。
      理由比原先硬了一档：不是「选择不读」，是**类型层面根本不存在** ——
      `@typeinfo` 吃的是类型，参数属性活在声明里，要读只能复活 `@fninfo`。
      目前编译器不消费任何参数属性 —— `fn f(#[unused] x: u32)` 是纯语法预留，
      将来编译器要用（如 lint）时才活。
      状态：已定

- [ ] **N9 测试框架：`#[test]` / `#[test("desc")]`**
      结论（已定的部分）：
        - 描述信息是字符串字面量，所以 `AttrArg` 要有 `Str` 变体。
        - 机制：编译器在编译时收集所有标了 `#[test]` 的函数，生成一张表
          ```rust
          struct TestCase {
            name: []u8,          // 函数名
            desc: []u8,          // #[test("...")] 的描述，没写则空
            run:  fn() -> (),
          }
          ```
          运行器遍历执行，失败即 panic。
        - 库做不到 —— xyz 没有遍历所有函数的能力，所以这是编译器特性。
        - `#[test]` 是**编译器消费的属性**，不需要反射读取 —— `@fninfo` 仍不做。
        - **测试是独立产物**，不是 debug 产物里的一个入口。
      待定三条已清（2026-09-26）：
        - **测试函数签名（用户改判：要 Result）**：`fn() -> ()` 与 `fn() -> E?()`
          都合法。`E?()` 版的语义：返回 `Err` 即该测试**失败**，运行器打印
          `Err` 载荷（走 K2 的反射打印）后该测试记失败、继续跑下一个 ——
          **不是** abort、不是跳过。这正是测试里用 `?` 的意义：`let f = open(p)?;`
          开头的测试，Err 直接判死，不用层层 match。验证错误**值**仍用断言
          （`assert(result == Err(expected))`）—— 要验的是值本身时轮不到
          运行器插手。
        - **不建第三种构建模式 `test`**：测试是独立产物，对它而言只有一种
          模式，没有「test 下 vs 非 test 下」的分叉；`#[build]` 照常生效
          （debug-only 代码在测试产物里按 debug 算）。构建模式是
          debug/release 的轴，测试是产物的轴，两轴不相交。
        - **运行器入口**：编译器生成的 shim 自己就是入口（同 main 的 shim
          机制），遍历 `TestCase` 表执行，不需要用户 main；测试产物里
          `fn main` 存不存在都无所谓（收集 `#[test]` 与找 main 是两件独立的
          事）。退出码：全过 `exit(0)`，有挂 `exit(1)`；单测 panic（abort）
          由 shim 转成「test failed」报告 —— 测试死在 panic 里也算失败，
          不算崩溃。`E?()` 版的 Err 失败**不**走 abort（K2 的退出三分是
          main 产物的语义，测试 shim 是另一个入口，Err 是普通控制流）。
      已落地（2026-09-26）：`01` Attributes 段语言属性表补 `#[test]`（第六个）；
      `11` Entry and artifacts 段补测试产物模型。
      追加（2026-09-26，PR #7）：Tests 段迁至新章 `13-testing.md`。
      状态：已落地（全部闭合）
