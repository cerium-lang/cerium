- [x] **X6 平台条件 #[cfg] + noreturn 声明（issue #114）**
      根因：std/sys/errno.ce 声明 `__errno_location`（glibc/musl
      拼法），Darwin 的 libSystem 同语义访问器叫 `__error`（链接
      符号 `___error`）——stdout/stderr 的 n<0 分支都调 sys::errno()
      → macOS 上几乎每个程序链接失败，make test 挂 211 项。其余
      std 符号（write/exit/fork/abort）全 POSIX 在 libSystem 有
      同名，glibc 专属拼写只有 errno 一个。修法（方案 2，已批准）：
      `#[cfg]` attribute 两维名单——系统 {linux, darwin} × 机器
      {amd64, arm64}（跟 qbe 后端对齐，arm64 一词盖 aarch64 与
      arm64_apple），args AND、多 attr AND、同维两名互斥报错、
      未知名报错、无 not（库列"支持谁"不列"排除谁"）、无 target
      triple（arm64_apple vs SysV 的 ABI 差是 qbe 的活，IL 层不可
      见）。**剔除点 = checkproject 开头重建 items vec**（cfgcull，
      pass 0）：被剔 item 不进 declare → use/impl/body/syms 平行
      性全不用动。errno.ce 双定义 `#[cfg(linux)]`/`#[cfg(darwin)]`
      各带自己的 extern 声明，每个编译只读一个。撞出两件事：
      （1）第一版 cfgattr 把"记维度名"和"匹配平台"混在一个分支
      里——`#[cfg(linux, darwin)]` 第一个 linux 走匹配分支不记
      sys，第二个 darwin 的互斥检查就查不到（`#[cfg(darwin,
      linux)]` 反而能报）——拆成先记后判两步；（2）itemcfg 最初
      early return 0，第二个 cfg attr 的 typo 会漏报，违反"culled
      分支上的 typo 与 kept 上的同响"原则——改全遍历。noreturn
      假阳性（issue #114 里两处 possibly-uninitialized）：eval.c
      与 operators.c 的 else 分支调 berr/cerrat（都 exit(1)）但
      声明未标 noreturn，Apple clang 数据流不知情——四处声明
      （die/cerrat/berr/voom）加 `__attribute__((__noreturn__))`，
      -pedantic 下双下划线扩展不告警。钉子：check/err 237（未知
      平台名）/238（同维互斥）/239（字面量 arg）/240（空 cfg）/
      241（darwin 剔除后调名 → unknown name，剔除先于 declare 的
      间接证明），run/239（linux+amd64+AND 组合正向）。probe：
      -T dump 不见被剔 item、整文件全剔的项目照常编译、cfg 挂
      use 双向（保留侧绑定成功/剔除侧 unknown name）。macOS 侧
      验证留给 Leo 本机 make test。
