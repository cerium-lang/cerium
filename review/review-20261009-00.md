# 线头 2026-10-09 · variadic 落地后（zip 全链）

## 语言 / 编译器

- [x] **X10 substargs 的 rows==1 二义——已修（本轮，y5 reveal 挖出）**
      根因：spread 的"绑定"与"参数顶着 pack"两种形态原先靠行数
      区分——argrows 对未绑定回 1，对恰好的 1-行 tuple 绑定也回
      nargs=1，同一个数两条路。1-行 zip 的实例化因此把已绑定的
      spread 当未绑定 keep，展开永远不发生：递归调用的返回类型
      reveal 出 `?(...([]i32,)::Item,)`——spread 原样留在结果里。
      修复：分发读 bind 本体（type.c substargs）——bind 空 / 非
      tuple / 非 unit → keep（模板自己的 substitution 继续走）；
      bind 是 tuple / unit → 按行数展开 argrow，一行也是展开。
      "the count alone never told the two apart"。
- [x] **X11 空 tuple 双拼写——已修（本轮，Some(()) 报错挖出）**
      根因：空 pack 的实例化产出 Tytuple(0,0)，而 `()` 字面量是
      Tyunit（parse 走 Nunit）——两个 intern 出来的不同指针，
      tysame 永假；adv 的空尾基例 Some(()) 于是报 "'Some'
      carries T here, () given"。修复：gsubstv 的 Tytuple case 行
      全花光时回 tyunit()（type.c，"the empty tuple's own one
      spelling, the literal's"），rexpr 的 Ntuple 同款（body.c）
      ——一个空 tuple 一种拼写，字面量的那个。
- [x] **X12 Nspread 值分组——重写落进 Ntuple 机器（本轮）**
      `(...its)`（pack 值参的分组形态）re-check 时 operand 已是
      绑定 tuple，原先落 berr "pack spreads arrive with generics"。
      修复：重写为 Ntuple[Nspread(operand)] 再 dispatch 回 rexpr
      （body.c）——Ntuple 已有的 spread 展开（Ntupidx 行 +
      sprrows/sprbases 移动记账）与 want-walk（行包 Tymut 槽）
      全部复用，Zip ctor 的 `Zip { its: (...its) }` 就是它；operand
      的 dispatch walk 套 movsnap（a look, not a take），真读在
      行上一次。
- 顺带记档：探针期望值 >255 被 exit 截断骗过一轮（405→149、258→2
  ——8 位截断；objdump 确认二进制本来就对，编译器无辜）。测试作
  者的坑：求和类探针的值域压回 255 内再下结论。
