      PR #96 留言的兑现：fmt 全家错误类型从 io::Error 换自己的
      fmt::Error（fmt/error.ce 新文件，Io(i32) 一变体，errno 藏在
      里面走，Fmt 自己拼 "io error N"）；? 的 same-E 语义
      （01-types.md Propagation）下两个错误相遇需要懂双方的手——
      map_err（std/result.ce，具名 fn 形态，闭包是 later
      milestone）就是那座桥，同 PR 落地。落地形态：trait Fmt 契
      约与九个 builtin impl 的 Error 换向（签名字面不动，use
      行删）；Writer 两个直调门（write_str/write_u8）走 ioerr 桥
      （`self.w.write(s).map_err(ioerr)?`）——嵌套 Io(io::Error)
      方案死于 X3 not-yet（std 内 root-relative qualified 不可
      用），内联 match 方案死于臂里不能 return（parse.c expr() 不
      收 Treturn，臂必须是表达式）——map_err + 具名桥 fn 是两条
      死路之后的活路，且恰好是 result.ce 新 API 的第一个 std 内
      用户；print.ce 的 Count sink 契约不动（io::Error），ns use
      `use std::io;` + 相对 qualified io::Error 拼出（X3 的现行

      加 errno() 固有方法（正经 API：想拿平台数字的手不必拆
      enum）+ impl Fmt 的签名换 fmt::Error（trait 契约 S1 后是
      fmt 的，跨 ns 签名同样走 ns use + qualified）。用户钉
