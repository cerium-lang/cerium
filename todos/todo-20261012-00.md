# 线头 2026-10-12 · MIR：一个中间表示，四个客户（提案）

## 名字与层次

叫 **MIR**，因为上面还会有一层：

```
tree（parser 的树）→ hir（宏落地时带来的一层）→ mir → ssa（qbe 的）
```

宏要的是一棵还能展开的树 —— 名字已解析、糖已脱、但仍是树的形状 ——
那是 hir；我们要的是控制流显式化的那层，是 mir。这样 mir 不是借
来的标签，是"它有上面一层"这件事的一部分。`14-macros.md` 现在论证
不要宏系统，结论故意留着 —— hir 随那个决定一起到，或者不到，mir
在它下面站着不动。

（`spine` 已被占：`resolve.c` 用它指 pass 管线那条主干。`walk` /
`row` / `frame` / `step` 都被用得很重，不再借。）

## 语言 / 编译器

- [ ] **MIR：先建，先不接客户（阶段 A）**
      现状：整个编译器没有中间表示。检查走树（pass 1–4），发射
      再走同一棵树两遍（pass 1 命名聚合体与实例化，pass 2 出文本）。
      借用检查靠 `Fenv.n`（绑定计数）当程序点：
      `freeze(x, fe, mut, (int) fe->n)`，绑定出作用域时 n 变小、
      比它大的借用自动 thaw —— 这是一套**词法**作用域的检查器，
      相当于 Rust 在 NLL 之前的形态，不用 CFG 也能跑。
      方案：每个函数一份 `Mirfn` —— locals（每个槽：绑定、临时、
      闭包 env）、blocks、regions。block = 若干指令 + 一个终结符。
      **分析用**：建起来、分析完、丢掉，发射继续走树（rustc 2016
      年就是这么做的：MIR 先只服务 borrowck）。
      第一步不接任何客户，只对全部测试跑一遍断言不崩 —— 零语义
      风险地验证 MIR 本身。

      形状（`src/mir.h`）：
      ```
      Mirfn   { Sym *fn; Mirplace *locals; Mirblock *blocks; Mirregion *regions; }
      Mirblock{ Mirinsn *insns; Mirterm term; }
      Mirinsn = Assign(place, rvalue) | Drop(place) | Call(dst?, fn, args)
      Mirterm = Goto(bb) | Branch(cond, bb, bb) | Switch(discr, arms, bb)
              | Return(v?) | Diverge               /* panic / noreturn */
      Mirplace = Local(i) | Field(p, name) | Index(p, v) | Deref(v) | Static(s)
      Mirvalue = Const | Copy(p) | Move(p) | Addr(p, mut) | Aggregate | Cast | …
      ```
      要点是 **place / value 分离** —— 不是照抄，是顺势：树层
      `rplace` 与 `rexpr` 已经在分这件事，MIR 只是把它固定下来。

      七个 Cerium 自己的决定：
      1. place 的路径词汇复用现有的（`placeroot` / `frzpath` 已在
         用 `.a.b` 串），阶段 D 迁移时靠得上。
      2. drop 变成显式指令（现在靠 pass 4 的 `scopedrops`），
         dropck 和可达性都随之好做。
      3. 切片也带区域，`[]T` = 指针 + 长度，区域挂在指针那半。
      4. 闭包 = 自己的 Mirfn + 一个 env place，捕获变成 env 字段
         读写。
      5. dyn 调用：`Call` 带 dyn 标志，对象安全规则不用动。
      6. **每个实例化一份 Mirfn**（跟 emit 的 `instensure` 一致）：
         泛型在 MIR 层已是单态的，区域分析不用处理泛型。
      7. **不做 SSA、不做 φ** —— SSA 是 qbe 的活（`-s` 出来那个）。
         槽可以重复赋值；做成 SSA 复杂度直接翻倍。

      文件：`src/mir.h`、`src/mir.c`（类型、遍历、打印）、
      `src/mirbuild.c`（树 → MIR，最大一块）。顺着 `-l` / `-a` /
      `-T` / `-s` 加一个 **`-i`** 打印 mir。

- [ ] **客户 B：可达性（只读，最安全，立刻见效）**
      #181 第 1 条。现在：一个 1 行的程序出 9575 行 SSA、237 个
      函数、`.text` 34,476 字节，98.4% 是没人调用的 std 行
      （`src/main.c` 自己写着 "nstd ignored: the whole unit is
      emitted"）。从入口（`main`，或测试表的每一行）走调用图
      标记，MIR 上是教科书操作，树上相当别扭。
      **为什么排第一**：它只能删代码 —— 删错了是编译失败，不是
      错代码。风险最低，收益最大。

- [ ] **客户 C：生命周期 / 逃逸检查**
      #185：`specs/01-types.md` 把 "returning the address of a
      local"、"returning a slice that outlives what it borrows"
      列为错误，但编译器只有一个极窄的检查（`body.c:5278` 的
      `localview`，只认裸 `[]T{...}` 字面量和 `a[0..2]`，且返回
      类型必须是 slice —— 指针根本进不去那个分支）。四个探针
      全被接受。
      有了 CFG，这一步**直接是流敏感的**：省掉"先做词法妥协、
      以后再升级到 NLL"的中间态。区域是 Mirfn 里的编号变量，
      约束 `R1: R2`（outlives）在赋值 / 调用实参 / 返回 / 存指针
      四处生成，并查集 + 约束图求解，活性走标准后向数据流。
      另有一处语法前提：`'a` 现在拼不出来 —— `lexbyte()` 要求
      `'x'` 成对，单写 `'a` 报 unterminated byte literal，要按
      Rust 的办法在词法层区分。

- [x] **客户 D：借用 / move / drop 迁移到 MIR（风险最高，最后）**
      结项（2026-10-14，#193–#199 六刀）：drop 指令显式化 → facts
      → move 影子（分歧即拒）→ MIR 前置到检查后 → 行级断言 →
      翻转（scopedrops 全拼、mirredecide 按流判决）→ cmv 删除。
      17 个钉子全程绿，289 程序 .ssa 逐字节不变。**未迁**（刻意，
      见 F）：freeze/thaw、`dead` 位、`loopd` 家族 —— 树侧 move
      检查在 -T（无 mid layer）下是唯一拒绝者；借用属语义升级
      （词法 thaw → NLL），两侧将答不同的题，翻法另议。

- [ ] **客户 E：async / await 降级（下一项）**
      定案（2026-10-14）：**E 是下一项**。无栈协程是 MIR 的
      killer client（rustc 的 async 降级跑在 MIR 上）：找挂起点、
      算跨挂起活性（进状态结构体）、切基本块为状态——树上做非常
      痛苦。E 的第一段路就是 F 的迁移（见下），随后是变换本体
      与 std 的 Future/Poll/block_on 面。

- [x] **客户 F：再决定发射要不要迁到 MIR**
      定案（2026-10-14，#200）：**迁，作为 E 的第一段路**。
      判据"E 真正需要"当天即满足——E 定为下一项。全量迁移需要
      rvalue 词汇覆盖 emit.c 4700 行的全部形状（聚合/内建/
      闭包/vtable/模式门控/常量折叠），按 D 的打法分刀推进、
      每刀 289 程序字节钉死。刀序：rvalue 词汇 → 真指令块 →
      MIR 发射器、树发射器退役 → E 的变换本体接上。迁移的第一
      笔收益：实例每 pass 重新 clone+recheck 的 wart 退役
      （mirfnnew 按名复用是它的补丁，迁移后 MIR 建一次、文本发
      两遍）。

## 记一笔

- 一个 MIR，不要按客户各建一个 —— 基本块 + 指令 + place/value
  分离这三样，四个客户都够用。过拟合给某一个客户是 rustc 踩过
  的坑（MIR 后来大改过）。
- **C 与 #181 第 2 条互斥**：无标注的跨函数分析（B 方案）依赖
  整单元编译；而生命周期注解一旦上了，签名自带跨函数信息，
  codegen unit 就能拆了。这两个决定绑在一起，要一起拍。
- 排除项：在发射出的 SSA 上做生命周期检查不可行 —— 太晚
  （诊断丢位置，而且 qbe 会先拒收）。
- A 阶段那个"先不接客户、只跑一遍建得出来"不只是谨慎，它也是
  最便宜的暴露方式：`mirbuild` 是最大的一块，让它先错在没有人
  依赖它的时候。
